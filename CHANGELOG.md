# Changelog

All notable changes to Open Game Launcher are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and this project adheres to [Semantic Versioning](https://semver.org/) as far as the AGPL-3.0 release permits.

## [Unreleased]

### Fixed

- Checkout now persists Stripe customer IDs in `store_customers` instead of non-existent `profiles.metadata`, and `stripe-webhook` is configured to accept external Stripe delivery without Supabase JWT verification.
- Stripe webhook HTTP handling now has a testable handler and adapter boundary covering CORS/method/signature guards, duplicate claims, checkout fulfillment/progress routing, order/license mutation plans, invoice persistence, refund ledger/status routing, unhandled event finalization, lease-token finalizers, and failure-ledger writes without live Stripe or Supabase secrets.
- Stripe checkout retries now carry a client-generated `checkout_attempt_id`, persist it per user, pass a matching Stripe idempotency key, and have extracted HTTP handler plus adapter coverage for auth/body/product/ownership/signing/free-order/paid-session/rollback paths, Supabase/Stripe query shapes, duplicate-attempt reuse, attach/session/cart failures, and session projection so repeated checkout attempts do not create duplicate paid sessions.
- Stripe webhook handling now records signed `event.id` values in a service-role-only replay ledger, short-circuits duplicate processed events, leases failed or stale in-flight events for retry, and marks failed events for explicit retry evidence.
- Remote Companion cloud job status updates now reject invalid jumps, keep terminal states immutable, and prevent queued jobs from being marked completed directly.
- Friend merge suggestion acceptance now reuses an existing target `merge_group_id` before creating a new group, keeps the final accepted-status update user-scoped, and keeps auto-match merge propagation scoped to matching owner/platform/platform-friend rows.
- Overlay cloud screenshot sync now uploads through the Supabase Storage helper instead of inserting local filesystem paths into screenshot metadata.
- Backup external-drive write-proof UI now sends the native command's expected mountpoint and explicit sentinel write/read/checksum/delete consent payload.
- Backup external-drive eject-safety UI now sends the native command's expected mountpoint and explicit flush/write/delete-before-eject consent payload.
- Backup external-drive OS-eject UI now sends the native command's expected mountpoint, preflight proof ID, and explicit OS unmount consent payload; success is only shown after the mount disappears from refreshed disk metadata.
- Supabase migrations now reset locally by giving screenshot likes a unique migration version and removing a `storage.objects` policy comment that required table ownership.
- Supabase migration functions now pass local `db lint --fail-on error`; share-token redemption avoids ambiguous table columns, and Remote Companion RPCs include `extensions` for `digest()`.
- Supabase friend migrations now include platform `og` in `platform_accounts`/`friend_links` checks, so native OG links are covered by the same hosted merge-group contract as imported provider links.
- Account deletion processing now claims due requests as `processing` before destructive storage/Auth deletion, blocks duplicate active requests across `pending` and `processing`, keeps claimed requests out of cancel scope, and surfaces audit-update failures instead of reporting a false processor success.
- `useLibrarySync` test suite: three pre-existing failures aligned with the refactored hook. The hook now uses `compressAndReadImage` (canvas + Image) instead of a raw `FileReader`, and the rejection message is more specific. Tests now mock `image-compress` directly and `waitFor` the first render before asserting.
- **Security (path-traversal)**: `commands/overlay.rs::delete_screenshot` now canonicalises the path and rejects anything outside the screenshots allow-root (`df11a4b`). The legacy `commands/mod_install.rs::scan_mod_directory` `#[tauri::command]` was removed (no callers; would have been a path-traversal sink).
- **Security (command-injection)**: New `commands/uri_safety` module centralises `validate_slug`, `validate_uri_scheme`, and `open_uri_safely` (`1743813`). The historical `cmd /C start "" <uri>` shell-out — which let any `&` in a URI become a command separator — has been removed from `crossplay.rs`, `system.rs`, and `games/core.rs::open_uri`. Windows now uses `rundll32 url.dll,FileProtocolHandler`, which doesn't parse the URI through a shell. The four `format!`-based URI builders in `commands/downloads/start.rs` (Steam/EA/Ubisoft/Battle.net) validate the slug before any string concatenation.
- **Security (WebView surface)**: `tauri.conf.json`'s `assetProtocol.scope` is no longer `["**"]` (`acb71fc`). It now allowlists `$APPDATA/**`, `$APPLOCALDATA/**`, `$APPCACHE/**`, `$HOME/**`, plus four explicit Steam library-cache paths. The `csp: null` setting has been replaced with a strict policy (`default-src 'self'`, `script-src 'self'`, `connect-src 'self' ipc: https://*.supabase.co`, `frame-src 'none'`, `object-src 'none'`, `form-action 'none'`).
